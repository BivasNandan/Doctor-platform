## Actual browser verification

The Vite app was served at `http://127.0.0.1:5173/Doctor-platform/` and interacted with using the configured CUA browser. Observed journeys: public directory and doctor profile; appointment slot/date selection and required-field validation; doctor registration and demo sign-in; doctor workspace; slot edit/block and appointment accept transition; admin sign-in/dashboard, doctor-management list/edit form, verification list; messages with a doctor-admin conversation and local simulated composition. A timezone bug and stale-form reset defect were found and fixed. The browser session exposed an intermittent CTA navigation issue during a later repeat attempt; the valid booking submission was therefore not counted as verified. File chooser/upload failure, account deactivation, all admin CRUD/status variants, mobile layout, and keyboard-only journeys were not fully exercised.

## Verification limits

- `npm run build` passes. `git diff --check` passes (Git reports only line-ending normalization warnings).
- `package.json` has no test, lint, or type-check script and no test-runner dependency. No automated test suite exists.
- Demo fixtures and demo service operations are in-memory, fictional, and reset on reload. A successful demo operation is never server persistence.
- Items marked backend dependency are not complete end-to-end features. See `FRONTEND_INTEGRATION.md` for the proposed contracts and backend work remaining.
